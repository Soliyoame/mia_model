# 思路 v7：以当前代码为准的 PCV-MIA 整体设计

更新时间：2026-06-03

这份文档是在 `思路v6.txt` 的基础上，对照当前仓库代码后整理出来的版本。注意：README 当前还没有同步更新，里面仍然有一些旧说法，例如 hashing embedding fallback、旧脚本编号等。因此本文件不以 README 为准，而是以当前代码、`configs/` 和 `scripts/` 为准。

当前方法仍然叫：

```text
PCV-MIA
Paired Counterfactual Verification Membership Inference Attack
```

中文可以叫：

```text
基于成对反事实验证的 RAG 知识库成员推理攻击
```

核心思想没有变：

> 只把 `KB_Member` 放入 RAG 知识库；从候选文档中抽取可验证、可替换的事实锚点；构造真实 claim 和反事实 claim；把它们包装成 Q+ / Q- 查询；同一组查询分别跑 RAG 和 LLM-only。如果 RAG 比 LLM-only 更能支持真实事实、否定反事实并纠正原实体，则这个差异更可能来自 RAG 知识库中的成员文档。

## 1. v6 和当前代码的主要差异

v6 是总体方法设计文档，很多方向是对的，但当前代码已经有几个关键变化。

### 1.1 脚本编号已经变成 01-15

v6 里还是旧顺序：

```text
09_run_rag_and_llm_only
10_parse_stance_and_score
11_run_baselines
...
14_generate_report
```

当前代码实际顺序是：

```text
01_preprocess_data.py
02_split_dataset.py
03_build_rag_index.py
04_generate_spoofed_nonmember.py
05_build_attack_benchmark.py
06_extract_facts.py
07_generate_paired_claims.py
08_generate_paired_queries.py
09_filter_stealth_queries.py
10_run_rag_and_llm_only.py
11_parse_stance_and_score.py
12_run_baselines.py
13_mechanism_analysis.py
14_run_defenses.py
15_generate_report.py
```

新增的关键步骤是第 09 步 `filter_stealth_queries`。所以以后所有说明、实验记录、重跑计划都应该按当前 01-15 编号写。

### 1.2 hashing embedding fallback 已经被移除

v6 和 README 里还保留过“hashing embedding 可用于低依赖跑通流程”的说法。当前代码已经不是这样。

现在：

```text
sentence-transformers/all-MiniLM-L6-v2 是默认真实 embedding 模型
hashing / hash backend 会直接报错
sentence-transformers 加载失败也会直接失败
```

核心文件：

```text
src/rag/embeddings.py
```

这样做的原因是：PCV-MIA 的 Retrieval Exposure、Query-Document Similarity、AUC、TPR/FPR 都依赖真实检索行为。如果底层 embedding 悄悄退回 hashing，实验结果会混入词面匹配偏差，不适合作为论文结果。

注意：当前代码仍然有一个 `json_vector_fallback`，但它不是 hashing embedding fallback。它只是在没有 FAISS 时，用 JSON 保存真实 embedding 向量。embedding 本身仍然来自 sentence-transformers。

### 1.3 事实抽取已经升级成 Attackable Fact Extractor

v6 中事实抽取还是：

```text
规则抽取金额、日期、百分比、医学剂量、合同期限
NER 抽取 PERSON、ORG、LOCATION
Sibling LLM 辅助生成 fact unit
固定 importance / replaceability / privacy_specificity 打分
```

当前代码已经改成：

```text
regex pattern registry
+ 可选 NER candidate generator
+ sentence quality gate
+ deterministic attackability scoring
+ entity family diversity selection
```

NER 的定位是可选候选源，不是最终事实决策器。当前代码默认没有加载 NER 模型，也没有引入新的 NER 依赖；如果以后要用 NER，可以通过 `EntityExtractor(ner_model=...)` 注入。
 ”当前代码默认没有加载 NER 模型，也没有引入新的 NER 依赖“是不需要NER模型吗？


• 结论：当前代码不需要 NER 模型也能跑；NER 是可选增强，不是必需依赖。

  现在的主流程靠的是：

  regex registry
  + sentence quality
  + attackability scoring
  + diversity selection

  也就是说，当前默认抽取器已经能抽：

  MONEY
  DATE
  TIME
  DURATION
  PERCENT
  MEDICAL_VALUE
  EMAIL
  URL
  PHONE
  SECTION_ID
  IDENTIFIER
  CONTRACT_TERM
  ORG
  LOCATION
  PERSON
  PRODUCT
  PROJECT_NAME
  NUMERIC_VALUE

  所以不加载 NER，pipeline 也能完整运行。

  NER 的作用是：补正则漏掉的实体，主要是提高 recall，例如更准地识别：

  PERSON
  ORG
  LOCATION
  LAW
  PRODUCT
  EVENT
  domain-specific named concepts

  但它不是必须的，因为 NER 只能回答：

  这是不是一个实体？

  而 PCV-MIA 真正需要的是：

  这个实体所在句子能不能构造成低 FPR 的可验证攻击 fact？

  所以当前设计是：

  NER = optional candidate generator
  regex + attackability = default decision framework

  如果你现在目标是先跑通和做论文主结果，我建议暂时不要默认启用 NER。原因是：

  不多引依赖
  不增加模型下载问题
  更可复现
  消融更清楚
  不容易因为 NER 误抽拉高 FPR

  更好的实验节奏是：

  主方法：regex registry + attackability extractor
  消融扩展：+ NER candidate generator

  论文里可以写：

  NER is supported as an optional recall-oriented candidate generator, but the default extractor is deterministic and
  dependency-light.

  如果后面发现 CUAD/PubMed/EDGAR 上 coverage 不够，再启用 NER 做 ablation。

### 1.4 新增了跨数据集实体族

当前抽取器不再只是 Enron 风格的 PERSON / ORG / EMAIL，而是按 entity family 管理：

```text
identifier:
  URL, EMAIL, PHONE, SECTION_ID, IDENTIFIER

structured_numeric:
  MONEY, MEDICAL_VALUE, PERCENT, NUMERIC_VALUE

date_time:
  DATE, TIME, DURATION

domain_term:
  CONTRACT_TERM, PRODUCT, PROJECT_NAME

named_entity:
  ORG, LOCATION, PERSON
```

这比“给 Enron 加更多规则”更通用。CUAD、PubMed、EDGAR、Enron 都能落在这些 family 下。

### 1.5 paired claim 的扰动逻辑已经同步扩展

为了配合新实体类型，当前代码已经扩展了同类型 counterfactual 生成：

```text
EMAIL: support@example.com -> alternate.contact@example.com
URL: https://example.com/report -> https://example.com/report/archive
TIME: 3:30 PM -> 4:00 PM
DURATION: 30 days -> 38 days
SECTION_ID: Section 5.2 -> Section 5.3
IDENTIFIER: Contract ABC-1234 -> Contract ABC-1241
PHONE: 212-555-0100 -> 212-555-0129
PROJECT_NAME: Project Atlas -> Project Beacon
PRODUCT: Atlas Platform -> Beacon System
```

这样新抽取出来的实体不会再大量走 `value + " revised"` 这种低质量 fallback。

### 1.6 Spoofed_Non_Member 仍然只是对照组

这一点和 v6 一致。

当前代码中 `Spoofed_Non_Member`：

```text
来自 Spoof_Seed
由 Sibling LLM rewrite + judge 生成
保留 entity/style/length 质量分
不进入 RAG index
只作为 hard negative / distribution-matched control
```

启用开关仍然是：

```text
PCV_ENABLE_SPOOFED_NONMEMBER=true
```

### 1.7 baseline 和 defense 目前部分是可运行骨架

当前 baseline 中已实现：

```text
PCV-MIA new version
Direct RAG-MIA
IA / Interrogation Attack
```

但以下仍是 reserved interface：

```text
S2MIA
MBA
RAG-leaks / difficulty-calibrated similarity baseline
E-MIA / exam-style QA baseline
```

当前 defense 也是可运行报告骨架，不是已经真正接入 generator 前的防御策略。它会输出 policy interface，但正式论文实验需要把 policy 接到 RAG generation 前重新跑。

## 2. 当前代码的一句话版本

当前代码实现的是：

> 一个以真实 sentence-transformers 检索为基础、严格隔离 `KB_Member` 和 non-member、用 Attackable Fact Extractor 抽取可验证事实、再通过成对反事实验证计算 RAG 相对 LLM-only context gain 的 RAG 知识库成员推理攻击框架。

更短一点：

```text
KB isolation
+ attackable fact extraction
+ paired counterfactual verification
+ RAG vs LLM-only context gain
= document-level membership score
```

## 4. 数据隔离边界

这是当前代码最重要的 invariant。

数据切分生成四组：

```text
KB_Member
True_Non_Member
Spoof_Seed
Reserve
```

可选生成第五组：

```text
Spoofed_Non_Member
```

进入 RAG index 的只有：

```text
KB_Member
```

绝对不能进入 index 的是：

```text
True_Non_Member
Spoof_Seed
Reserve
Spoofed_Non_Member
```

当前代码在两个地方做保护：

1. `splitter.py` 给 `KB_Member` 标记 `in_knowledge_base=True`，其他组为 false。
2. `index_builder.py` 在构建 index 前再次检查所有输入 row 的 `group` 必须是 `KB_Member`。

如果非 member 样本被传入 index builder，会直接报错。



## 10. Stage 06：抽取可验证事实

入口：

```text
scripts/06_extract_facts.py
src/fact_extraction/fact_extractor.py
src/attack/entity_extractor.py
```

这是当前代码和 v6 相比变化最大的部分。

### 10.1 当前抽取器的四层结构

当前实体抽取不是线性：

```text
正则抽实体 -> 固定分数 -> 阈值过滤 -> top-k
```

而是：

```text
candidate generation
↓
candidate normalization / merge
↓
sentence-level context analysis
↓
attackability dynamic scoring
↓
hard gates
↓
diversity selection
```

### 10.2 candidate generation

高精度骨架来自 regex registry：

```text
PATTERN_REGISTRY
```

每个 pattern 有：

```text
entity_type
entity_family
pattern
base_scores
priority
source
```

可选 NER：

```text
EntityExtractor(ner_model=...)
```

NER 支持 spaCy 风格对象，也支持 HuggingFace pipeline 风格 dict。NER 输出会被映射到内部类型：

```text
PER / PERSON -> PERSON
ORG / ORGANIZATION -> ORG
GPE / LOC / LOCATION / FAC -> LOCATION
LAW -> CONTRACT_TERM
PRODUCT -> PRODUCT
EVENT -> PROJECT_NAME
```

但 NER 只是候选源。NER confidence 只作为小 bonus，不直接决定 fact 是否入选。

### 10.3 sentence quality

每个候选实体都会找到所在句子，并计算：

```text
sentence length 是否合适
是否有 relation cue
是否有多个 anchor entities
是否是 template / boilerplate
是否是 header / footer / signature
实体是否只是孤立句子
```

低质量句子会被 hard gate 过滤。例如：

```text
Regards, John
```

不会变成高质量 fact。

### 10.4 attackability score

当前动态分数包含：

```text
base type score
context_quality
specificity
replaceability
retrieval_anchor_strength
parser_friendliness
source_agreement
NER confidence bonus
generic_penalty
```

输出仍然保留旧字段：

```text
importance
replaceability
privacy_specificity
```

同时新增：

```text
entity_family
attackability_score
specificity
context_quality
retrieval_anchor_strength
parser_friendliness
generic_penalty
context_reasons
candidate_sources
selection_reason
extractor_version: attackability_v1
```

### 10.5 diversity selection

当前默认 family quota：

```text
structured_numeric: 2
date_time: 1
identifier: 1
named_entity: 1
domain_term: 1
```

这避免 PERSON、ORG 或纯数字占满每篇文档的候选事实。

### 10.6 fact schema

`fact_extractor.py` 会把 entity 转成 fact unit：

```text
fact_id
audit_id
doc_id
dataset
group
subject
relation
object_entity
entity_type
context
supporting_sentence
factual_claim
importance
replaceability
privacy_specificity
entity_metadata
```

新增的 attackability 信息不破坏下游，而是放在：

```text
entity_metadata
```

这保证 paired claims、queries、scoring 不需要大改。

## 13. Stage 09：Stealth Filter

入口：

```text
scripts/09_filter_stealth_queries.py

```

这一阶段是 v6 之后新增的。

目的不是提升攻击强度，而是过滤明显不像自然用户查询、或者明显在探测系统上下文的 query。

过滤信号包括：

```text
dangerous terms
prompt injection pattern
context probing pattern
naturalness score
query_doc_similarity
```

当前默认配置：

```text
embedding_model: sentence-transformers/all-MiniLM-L6-v2

max_context_probe: 0.5
max_prompt_injection: 0.5
min_similarity: 0.03
max_similarity: 0.97
```

输出：

```text
accepted queries -> outputs/stealth_filtered_queries/
rejected queries -> *_rejected.jsonl
manifest -> accepted / rejected / stealth_detection_rate
```

## 14. Stage 10：RAG 和 LLM-only 双路推理

入口：

```text
scripts/10_run_rag_and_llm_only.py
src/rag/runner.py
src/rag/retriever.py
```

同一条 query 同时跑两种模式：

```text
RAG mode:
  query -> retriever -> top-k context -> generator

LLM-only mode:
  query -> no private retrieved context -> same generator
```

RAG prompt 明确要求：

```text
Use only the available documents below.
If conflict, state inconsistent and provide corrected value.
If documents do not support verification, say do not know.
```

LLM-only prompt 明确说明：

```text
no private retrieved documents are available
if cannot verify from query alone, say do not know
```

这样设计是为了让 RAG 和 LLM-only 的差异主要来自 retrieved context，而不是 generator 自己自由发挥。

输出分开保存：

```text
outputs/rag_responses/{dataset}_rag_responses.jsonl
outputs/llm_only_responses/{dataset}_llm_only_responses.jsonl
```

RAG response 还记录：

```text
retrieved_doc_ids
retrieval_scores
target_doc_retrieved
generation_config
```

这些字段只用于机制分析，不直接作为黑盒 membership score 的输入。


对 Q+：

```text

```

对 Q-：

```text

rejects_counterfactual

unrelated
```

### 15.2 scoring

核心公式：

```text
CVG = SupportScore(Q+) + CorrectionScore(Q-) - FalseAcceptancePenalty(Q-)
CG-CVG = CVG_RAG - CVG_LLM
PCV_SCORE = average(CG-CVG over document pairs)
```

当前默认：

```text
unknown_lambda: 0.5
refusal_penalty: 0.5
false_acceptance_penalty: 1.0
thresholds: [0.3, 0.5, 0.7, 1.0]
```

文档级输出：

```text
audit_id
dataset
group
num_pairs
cvg_rag
cvg_llm
cg_cvg
pcv_score
support_true_count_rag
correct_counterfactual_count_rag
accept_false_count_rag
unknown_rate_rag
unknown_rate_llm
predicted_member_t*
```

当前成员分数就是：

```text
pcv_score = cg_cvg
```

## 22. 当前方法适用范围

这套方法适合：

```text
文本型 RAG 数据集
文档里有可验证事实
事实里有具体实体
实体可以被同类型替换
RAG 能检索回支持句
parser 能判断 consistent / inconsistent / unknown
```

适合的数据集例子：

```text
Enron: email, person, org, date, time, meeting/event
CUAD: section, clause, party, date, duration, legal term
PubMed: dose, duration, patient count, percent, disease/drug term
EDGAR: money, percent, date, org, section, financial term
```

不适合：

```text
纯观点文本
极短文本
诗歌/小说/抽象评论
匿名化严重、实体很少的文本
只有标签没有事实的分类数据
大量表格但没有自然语言支持句的文档
```

原因是 PCV-MIA 不是做实体识别本身，而是需要构造：

```text
真实可验证事实
vs
最小同类型反事实错误
```

## 24. 当前尚未完成或需要注意的点

1. README 已经过期

README 中仍有 hashing fallback、旧依赖定位和部分旧说明。当前实验应以本文件和代码为准，后续需要单独更新 README。

2. NER 只是接口，不是默认流程

当前 `EntityExtractor` 支持注入 NER，但没有自动加载 NER 模型，也没有配置项暴露 NER。论文里如果不实际启用 NER，就不能把 NER 作为正式实验组件写进主结果，只能写成 optional extension。

3. Defense 只是接口

当前 defense report 不是实际防御后重跑结果。正式报告 defense 需要重新接入 RAG generation。

4. 部分 baseline 是 reserved

S2MIA、MBA、RAG-leaks、E-MIA 目前不是完整实现，不能当已完成 baseline 报告。

5. Top-k sensitivity 和 nearest-neighbor similarity 仍需补

机制分析当前已经有核心 exposure/evidence/context gain，但最近邻非成员误报分析和 top-k 消融还没有真正跑全。

6. fact_extractor 仍是轻量规则化 fact builder

`entity_extractor.py` 已经升级为 attackability extractor，但 `fact_extractor.py` 的 subject/relation/context 仍是轻量规则从句子中抽取，不是复杂事件抽取器。它的优点是可复现、低依赖；缺点是 relation 可能不够语义化。

## 25. 最终总结

v6 的总体方向是对的：PCV-MIA 的核心仍然是成对反事实验证和 RAG/LLM-only context gain。

但当前代码已经比 v6 更具体、更严格：

```text
1. 脚本顺序更新为 01-15，并新增 stealth filter。
2. hashing embedding fallback 已移除，正式使用真实 sentence-transformers。
3. RAG index 只允许 KB_Member，代码层面有硬检查。
4. benchmark 固化并保存 sha256。
5. 事实抽取升级为 Attackable Fact Extractor。
6. NER 是可选候选源，不是最终 fact 决策器。
7. 新增跨数据集实体 family 和 attackability score。
8. paired claim 扰动逻辑已覆盖新实体类型。
9. baseline 和 defense 目前区分了已实现部分与 reserved interface。
10. mechanism analysis 已能解释 exposure、evidence、correction、false acceptance 和 context gain。
```

因此，当前代码思路可以概括为：

> **用严格隔离的 KB_Member 构建真实语义 RAG index；从所有候选文档中用可复现的 Attackable Fact Extractor 抽取适合攻击的事实锚点；构造真实 claim 与最小同类型反事实 claim；生成自然验证查询并过滤明显攻击式 query；对同一查询分别运行 RAG 和 LLM-only；用 stance parser 把回答转为支持、否定、纠正、未知等信号；计算 RAG 相对 LLM-only 的 CG-CVG，作为文档级 membership score。Spoofed_Non_Member、baseline、mechanism analysis 和 defense 是实验评估层，不是 PCV-MIA 主方法本体。**
