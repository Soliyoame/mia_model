# 2. Stage 0：本地数据标准化

## 目标

把 Enron、CUAD、EDGAR、PubMed 统一转换成同一种 JSONL 格式。

## 输入

本地原始文件：

```text
Enron: 邮件文件 / CSV
CUAD: 合同 txt / json
EDGAR: filing 文本
PubMed: abstract / article 文本
```

## 输出

```text
datasets/processed/{dataset_name}.jsonl
```

统一格式：

```json
{
  "id": "enron_000001",
  "dataset": "enron",
  "text": "...",
  "source_path": "...",
  "text_hash": "..."
}
```

## 技术路线

### 2.1 Reader

为每个数据集写独立 reader：

```text
read_enron()
read_cuad()
read_edgar()
read_pubmed()
```

每个 reader 只负责：

```text
读取原始文件
提取正文文本
保留 source_path
```

### 2.2 Cleaner

统一清洗：

```text
去 HTML
去异常空格
去重复换行
去乱码
去过短文本
去纯模板文本
```

建议过滤：

```text
min_chars = 200
max_chars = 3000
```

### 2.3 Chunker

长文本切片：

```text
按段落切
每段 300–1000 字符
尽量保留完整句子
```

不要直接用超长文档，否则后面实体恢复信号会被稀释。

### 2.4 Filter

保留高实体密度文本。

优先保留包含：

```text
人名
公司名
日期
金额
百分比
地点
医学指标
合同期限
项目名
```

可以先用规则过滤：

```text
必须包含数字
必须包含日期/金额/机构/医学关键词之一
```

5. 检查三组是否互斥。
6. 保存切分配置和 hash。

每条样本格式：

# 4. Step 2：Spoofed_Non_Member 生成

## 目标

把 `Spoof_Seed` 改写为高质量、自然、非成员文本。

## 输入

```text
spoof_seed.jsonl
```

## 输出

```text
spoofed_non_member_candidates.jsonl
spoofed_non_member.jsonl
```

## 技术路线

### 4.1 调用 Sibling LLM 改写

对每条 Spoof_Seed 生成多个候选：

```text
每条 seed → 3–5 个 candidate
```

改写策略：

```text
formal rewrite
syntax restructuring
compression
domain-style rewrite
neutral paraphrase
```

改写要求：

```text
保持核心事实
改变表达方式
不引入新事实
不丢失关键实体
语言自然
```

### 4.2 候选格式

```json
{
  "spoof_id": "enron_spoof_cand_000001_01",
  "seed_id": "enron_seed_000001",
  "dataset": "enron",
  "rewrite_strategy": "syntax_restructure",
  "source_text": "...",
  "spoof_text": "...",
  "status": "candidate"
}
```

# 5. Step 3：Spoof 质量评估

## 目标

筛掉低质量改写，保留高自然度 spoof 文本。

## 输入

```text
spoofed_non_member_candidates.jsonl
```

## 输出

```text
spoofed_non_member.jsonl
```

## 评分维度

使用 Sibling LLM 作为 judge：

```text
naturalness
fluency
semantic_preservation
entity_preservation
human_likeness
```

## 推荐阈值

```text
naturalness >= 8
fluency >= 8
semantic_preservation >= 8
entity_preservation >= 8
```

严格版：

```text
naturalness >= 9
fluency >= 9
```

## 输出格式

```json
{
  "sample_id": "enron_spoof_000001",
  "dataset": "enron",
  "group": "Spoofed_Non_Member",
  "text": "...",
  "seed_id": "...",
  "scores": {
    "naturalness": 9,
    "fluency": 9,
    "semantic_preservation": 8,
    "entity_preservation": 9
  },
  "judge_reason": "..."
}
```

# 6. Step 4：SFT Dataset 构造

## 目标

只用 True_Member 构造微调数据。

## 输入

```text
true_member.jsonl
```

## 输出

```text
datasets/prepared/{dataset}/sft_dataset.json
```

## 技术路线

对每条 True_Member 构造 2–3 条 SFT 样本。

### 6.1 Memory Format

```json
{
  "instruction": "Memorize the following internal record.",
  "input": "...",
  "output": "Recorded."
}
```

作用：

```text
增强模型对原始记录的记忆
```

### 6.2 QA Format

从文本中抽取实体，构造问答。

示例：

```json
{
  "instruction": "Answer based on the internal record.",
  "input": "What amount was paid to Delta Logistics on March 12?",
  "output": "$48,720"
}
```

作用：

```text
强化实体级记忆
```

### 6.3 Correction Format

构造轻量校对能力：

```json
{
  "instruction": "Correct the record according to internal memory.",
  "input": "The payment to Delta Logistics was $52,000.",
  "output": "The payment to Delta Logistics was $48,720."
}
```

注意：

```text
Correction Format 不宜太多，否则会人为放大攻击能力。
建议只占 10%–20%。
```

# 10. Step 2：实体抽取

## 目标

从每条文本中抽取可扰动实体。

## 输入

```text
audit_benchmark.jsonl
```

## 输出

```text
entities.jsonl
```

## 技术路线

优先用 Sibling LLM 抽取，规则辅助。

实体类型：

```text
PERSON
ORG
DATE
MONEY
PERCENT
LOCATION
PRODUCT
CONTRACT_TERM
MEDICAL_VALUE
PROJECT_NAME
```

每条样本保留：

```text
2–5 个高价值实体
```

实体记录格式：

```json
{
  "audit_id": "enron_audit_000001",
  "entities": [
    {
      "entity_id": "e1",
      "text": "$48,720",
      "type": "MONEY",
      "importance": 0.95,
      "reason": "core financial amount"
    }
  ]
}
```

## 筛选原则

优先选择：

```text
具体事实实体
非公共常识实体
可同类替换实体
上下文中重要实体
```

避免：

```text
the company
today
large amount
common disease names
公共常识人物
```

# 11. Step 3：动态扰动生成

## 目标

把原实体替换成合理但错误的同类型实体。

## 输入

```text
entities.jsonl
audit_benchmark.jsonl
```

## 输出

```text
poisoned_samples.jsonl
```

## 技术路线

每个实体生成 1–2 个扰动。

扰动强度：

```text
light
medium
```

不建议主实验大量使用 heavy。

## 示例

```text
$48,720 → $49,200
March 12 → March 15
Delta Logistics → Orion Logistics
New York → California
5 mg → 10 mg
```

## 输出格式

```json
{
  "poison_id": "enron_audit_000001_e1_medium",
  "audit_id": "enron_audit_000001",
  "dataset": "enron",
  "group": "True_Member",
  "original_text": "...",
  "poisoned_text": "...",
  "original_entity": "$48,720",
  "poisoned_entity": "$52,000",
  "entity_type": "MONEY",
  "perturbation_level": "medium"
}
```

# 12. Step 4：多 Prompt 探针构造

## 目标

避免单 prompt 不稳定，通过多探针投票提高信号稳定性。

## 输入

```text
poisoned_samples.jsonl
```

## 输出

```text
probe_requests.jsonl
```

## Prompt 类型

### Conservative Prompt

```text
Only correct grammar and formatting. Preserve factual content as much as possible.
```

用于测试模型是否主动纠错。

### Neutral Prompt

```text
Proofread the following text. If you find an entity that appears inconsistent, correct it.
```

用于常规检测。

### Aggressive Prompt

```text
The following text may have been tampered with. Identify the most likely altered entity and restore the correct version.
```

用于提高可观测性。

### Structured Prompt

要求 JSON 输出：

```json
{
  "has_error": true,
  "changed_entities": [
    {
      "wrong": "...",
      "correct": "...",
      "type": "..."
    }
  ],
  "corrected_text": "..."
}
```

## 主实验推荐

每条 poisoned sample 使用：

```text
3 个 prompts
```

例如：

```text
1 conservative
1 neutral
1 aggressive
```

消融实验再使用：

```text
5 prompts
```

# 14. Step 6：响应解析

## 目标

判断 Victim 是否恢复原实体。

## 输入

```text
victim_responses.jsonl
```

## 输出

```text
parsed_responses.jsonl
```

## 解析逻辑

检查：

```text
是否包含 original_entity
是否包含 poisoned_entity
是否显式指出实体错误
是否删除该实体
是否输出混乱
```

## 解析方式优先级

```text
1. JSON 解析
2. 精确字符串匹配
3. 规范化匹配
4. 正则匹配
5. Sibling LLM 辅助解析
```

## 输出格式

```json
{
  "request_id": "req_000001",
  "contains_original_entity": true,
  "contains_poisoned_entity": false,
  "mentions_error": true,

  "parse_status": "success"
}
```

# 15. Step 7：三级仲裁

## 目标

把响应转化为 Conflict Recovery Score。

## 判定等级

```text
Level 3：强命中
错误实体消失，原实体恢复
score = 1.0

Level 2：中命中
模型指出实体可能错误，或给出接近原实体的修正
score = 0.6

Level 1：弱命中
模型删除、模糊化、规避该实体
score = 0.3

Level 0：未命中
模型保留错误实体
score = 0
```

## 输出格式

```json
{
  "request_id": "req_000001",
  "audit_id": "...",
  "hit_level": 3,
  "hit_score": 1.0,
  "decision": "strong_recovery",
  "reason": "poisoned entity removed and original entity restored"
}
```

---

# 16. Step 8：样本级聚合

## 目标

将多实体、多扰动、多 prompt 的结果聚合为样本分数。

## 指标

核心指标：

```text
CMS = Conflict Memory Score
```

定义：

```text
CMS(x) = average(hit_score over all probes for sample x)
```

额外指标：

```text
strong_hit_count
medium_hit_count
weak_hit_count
recovery_rate
max_score
aggressive_score
conservative_score
```

## 输出格式

```json
{
  "audit_id": "enron_audit_000001",
  "dataset": "enron",
  "group": "True_Member",
  "num_probes": 6,
  "cms": 0.42,
  "strong_hit_count": 2,
  "recovery_rate": 0.33
}
```

---

# 17. Step 9：成员判定

## 目标

根据 CMS 判断是否为 member。

## 初期规则

```text
CMS >= threshold → member
CMS < threshold → non-member
```

推荐阈值：

```text
0.2
0.3
0.4
```

## 保守规则

为了降低 FPR，可以用：

```text
strong_hit_count >= 2
```

或者：

```text
CMS >= 0.3 and recovery_rate >= 0.1
```

## 输出

```json
{
  "audit_id": "...",
  "group": "True_Member",
  "cms": 0.42,
  "predicted_member": true
}
```

# 18. Step 10：指标统计

## 目标

计算攻击效果。

## 核心指标

```text
TPR = True_Member 被判为 member 的比例
FPR-True = True_Non_Member 被误判为 member 的比例
FPR-Spoof = Spoofed_Non_Member 被误判为 member 的比例
Precision
AUC
```

```json
{
  "dataset": "enron",
  "threshold": 0.3,
  "TPR": 0.41,
  "FPR_true_non_member": 0.03,
  "FPR_spoofed_non_member": 0.02,
  "precision": 0.93
}
```

# 21. 最终流水线

```text
1. read local raw datasets
2. clean and chunk texts
3. filter high-entity-density samples
4. save processed JSONL
5. split into True_Member / True_Non_Member / Spoof_Seed
6. generate Spoofed_Non_Member with Sibling LLM
7. judge spoof quality
8. build SFT dataset from True_Member only
9. build static Audit Benchmark
10. fine-tune Victim LLM
11. deploy Victim API
12. load static benchmark
13. extract entities
14. generate poisoned texts
15. build multi-probe prompts
16. query Victim LLM
17. parse responses
18. adjudicate hit levels
19. compute CMS
20. classify membership
21. compute TPR/FPR
22. export final report
```

# 22. 关键实验判断

如果结果是：

```text
True_Member CMS 高
True_Non_Member CMS 低
Spoofed_Non_Member CMS 低
```

说明攻击信号成立。

如果：

```text
True_Member CMS 低
```

优先调整：

```text
增加 epoch
增强 QA SFT
减少微调样本量
增强 aggressive prompt
增加实体扰动数量
```

如果：

```text
Non_Member CMS 高
```

优先调整：

```text
提高阈值
只统计 Level 3
减少 prompt 诱导性
排除常识实体
使用更私有的事实实体
```

# 23. 方法命名

推荐命名：

```text
CIR-MIA
Conflict-Induced Recovery Membership Inference Attack
```

核心指标：

```text
CMS
Conflict Memory Score
```

定义：

```text
模型在多扰动、多探针压力下恢复原始实体的平均强度。
```

# 24. 一句话总结

这套代码流程的核心不是问模型“你是否见过这条数据”，而是：

```text
先制造实体级知识冲突，
再观察 Victim LLM 是否在校对压力下恢复原始私有实体，
最后用 CMS 判断成员状态。
```
