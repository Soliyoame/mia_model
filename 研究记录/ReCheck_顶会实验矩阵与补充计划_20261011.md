当前为 Gemma-2-2B、BGE dense、seed=45，每库 1000 Member＋1000 Nonmember，评价单位为 source document。主方法采用三值式：

## 3. 如何参考 MEntA 的规模

MEntA 主表采用三个 BEIR 数据集，每库 1000 成员＋1000 非成员，四个 Generator 为 Gemma2-2B、Llama3.1-8B、CommandR-7B、Phi4-14B；比较 IA、MBA、S²-MIA、DCMI。MEntA 的默认查询预算为 5，主检索设置为 all-mpnet-base-v2、top-k=3。[论文 §6.1 与 Table 3](https://arxiv.org/html/2605.24312v1#S6.SS1)

论文用 Llama3.1-8B 研究检索变化，用 Phi4-14B 研究防御，说明“主表广覆盖、扩展实验选代表模型”是可参考的组织方式。[论文 §6.6–6.7](https://arxiv.org/html/2605.24312v1#S6.SS6)

本项目采用其规模作为规划参考，主设置继续沿用当前 BGE/top-k=5，最终各方法在同一 RAG 上比较。现阶段先引用原论文数字，最终同条件复现放到F阶段。这里提出的优先级和样本安排是 ReCheck 的计划，不是 MEntA 的原实验。

### 7.2 门控与额外独立问题

代表模型预定为 Gemma2-2B＋Llama3.1-8B，三库各用固定1000＋1000来源。K始终来自该模型的三条初问；所有分支、槽位顺序、随机seed和评分公式在新增响应前固定。

| 对照 | 查询数/文档 | 评分或选槽定义 | 回答的问题 |
|---|---:|---|---|
| 仅初问 | 3 | C 与 C−U分别报告 | 二阶段整体增益与代价 |
| ReCheck | 3＋K | 只追问初问答对的槽，主三值式 | 主方法 |
| 同数量独立问题 | 3＋K | 额外问题预先生成并固定顺序，取前K条；分数为 C−U＋λ×额外回答的三值和 | 增益是否仅来自增加查询或独立事实覆盖 |
| 所有槽都追问 | 6 | 三个槽均执行追问，全部追问三值和进入分数，不乘初问正确指示 | 门控的调用节省与信息损失 |
| 随机槽位、同数量追问 | 3＋K | 按文档seed预先排列三个槽，取前K个，不按槽的初问正确性选；三值和进入分数 | 相同调用数下，按正确性选择槽是否有价值 |

具体定义：对有效回答令ψ=1（正确）、−1（拒答）、0（其他）；缺失或传输失败不定义ψ。令g_i表示第i条初问是否正确，K=Σg_i，f_i为对应追问，π为预先固定的随机槽位排列，e_j为固定序列中的额外独立问题。ReCheck分数为C−U＋λΣ_{i:g_i=1}ψ(f_i)，全槽追问为C−U＋λΣ_{i=1..3}ψ(f_i)，随机K槽为C−U＋λΣ_{j=1..K}ψ(f_{π_j})，独立问题为C−U＋λΣ_{j=1..K}ψ(e_j)。K=0时后两式的额外求和为0。仅对实际需要且完整的响应计算相应分数；全槽和随机分数不再乘g_i。

同数量独立问题应针对其他独立事实，不能只改写同一问题。每篇最多需要预构造三条额外事实问题，构造模型与核验标准固定。现有资格只保证当前主方法的事实需求，不保证还能构造三条额外问题；因此先在固定来源上检查覆盖，失败不按成员或攻击结果删除。若必须改动来源资格才能完成对照，另标为不同条件人群，不能原地替换已有split或把其结果当原cohort。

三个槽的主方法追问已在现有query plan中预先构造；初问答错的槽在控制臂仍使用该槽同一固定追问，初问响应只决定gate，不用于重新生成问题或改写前提。机制响应复用还须核对完整请求、检索上下文、对话历史、请求顺序影响、缓存语义、模型revision及解码设置。当前执行器逐请求发送固定RAG提示；如后续服务引入会话状态而无法证明兼容，则控制臂重新采集，不拼接不同历史的响应。补采控制臂单独保存，不向旧主方法文件加入超出原gate的回答。

为节省采集，可保留原初问和已触发追问，只补齐未触发的三个槽响应，得到“所有槽都追问”的材料，再按预先定义的随机选槽离线计算。另收集K条独立问题响应。请求、模型、检索和输出配置相同时，每篇理想新增 (3−K)＋K＝3 次 victim 调用，两模型三库12000个文档×模型观测合计新增约36000次；构造失败、版本不兼容与重试另计。实验采集共享成本和每种攻击独立部署成本分别报告。

### 7.3 逐文档机制结果

以同一固定阈值2比较 C−U 与完整分数，至少给出：

- 非成员：初问误报→正确拒绝的数量与比例；初问正确拒绝→新增误报的数量与比例。
- 成员：初问检出→仍检出的保留率；初问检出→漏检的损失；原漏检→新增检出。
- K=0/1/2/3 各层的成员/非成员数量、追问正确率与拒答率、平均调用数及来源分数分布。
- 固定阈值结果与经验低FPR结果分别展示；若误报下降伴随成员检出下降，明确报出权衡。

不能仅用 AUC 上升证明“纠正误报”，也不能把只分析K>0人群的结果外推到全部文档。共享追问目标带来的相关性由来源级统计处理，多个槽不是独立样本。

## 8. 评分消融与统计口径

评分组件与λ敏感性沿用已有诊断，先补齐第三库，再在代表模型新结果上作固定定义的确认。至少比较 C、C−U、C＋R、C−U＋R、C−U＋R−V，并展示各自低FPR、查询数与固定阈值代价。不能只展示对新式有利的指标。

主评估采用 source AUROC＋TPR@经验FPR≤1%；5%为补充，0.1%为分辨率受限的探索指标。每库1000非成员只有0.1%的非零经验FPR步长；零误报不是总体零FPR保证。报告可达阈值、实际FPR、误报计数及区间，离散评分不插值制造更好操作点。

| 统计项目 | 统一规则 |
|---|---|
| AUC、AP、TPR/FPR、查询成本 | 逐数据集、逐Generator、逐Retriever报告 |
| AUC及方法差值区间 | membership内分层、整篇source配对bootstrap，2000次，预先固定seed |
| 低FPR方法差值区间 | 同一source重抽，按固定ROC选点定义在每次重抽中重新计算；注明低计数不稳定 |
| 固定阈值2 | 报混淆矩阵、TPR/FPR、Precision/F1/MCC及计数区间，不能在test挑最佳accuracy阈值 |
| macro | 同一攻击方法、Generator、Retriever、该方法判分版本和评估角色内，各数据集等权；不跨backend混合 |
| 多重比较 | 当前做ReCheck vs 同数量独立问题、ReCheck vs 随机槽；F阶段补ReCheck预算5 vs MEntA5。仅对本项目同条件结果计算配对检验；需p值时对声明的检验集合校正 |
| 类别比例 | 1:1是基准采样；AP/Precision不直接外推到低成员先验，先验分析单列 |
| 重复来源或槽位 | 不增加独立样本量，方法和模型共享来源时保留配对关系 |

如需要部署阈值，在开发数据中按预定目标选取后冻结，后续固定评估只报告其实际表现；作为另一个操作规则单列，不能回改已有阈值2或把test ROC选点当部署阈值。

## 10. P2：防御、效用与实际成本

默认Phi4-14B×三库各1000＋1000，当前先做ReCheck。无防御主设置复用；新增三项分别执行，不做所有组合，MEntA对照在F阶段补：

| 防御 | 预先固定的条件 | 必报内容 |
|---|---|---|
| 指令防御 | 固定系统提示及泄漏抑制规则 | 攻击AUC/低FPR、正常问答变化、拒答率 |
| 查询语义改写 | 固定改写模型/版本、Prompt、参数；保留问题条件与目标语义 | 攻击性能、改写错误率、额外调用/token/延迟 |
| 检索rerank | 固定reranker/revision、候选深度及最终k | 攻击性能、正常检索质量和延迟 |

以上共9个新增系统设置：先完成ReCheck的9个结果单元，最后补MEntA的9个，合计18个。若决定追加IA防御对照，同样在F阶段执行，增加其victim及shadow成本。没有观察到显著效果的防御也完整报告。

每库预选200条与攻击不同的正常BEIR查询，比较无防御及各防御下的Recall@k/nDCG、回答拒答与成本。BEIR的qrels不等同于问答金标准：回答正确性只在有可靠参考答案或独立审阅的子集报告，并注明覆盖率。不能用“让模型全部拒答”当作兼顾效用的隐私防御。

若论文主张难检测，再做检测器实验：分开校准/测试正常查询、报告攻击检出率与正常FPR，多个攻击问题按来源聚类。正常测试查询数量要足以估计声称的低FPR，不能仅用上述200条效用查询证明1%检测FPR。没有该实验则不宣称隐蔽性。

具有明确隐私定义的DP防御属于P3，需要具体机制、邻接定义和隐私参数；任意输出噪声或改写不直接称DP。不为凑防御数量新增无明确研究目的的机制。

## 14. 实现与复现保持简单

优先扩展现有shared_g执行/来源/检索能力、answer_judgment.py和source_scoring.py，以及现有104/105入口、共享llm_profiles和受影响测试。基线代码在当前工作树中有既有删除，需先确认原方法实现与删除归属；不自动恢复用户删除的整套历史流水线，不把旧治理系统带入新功能。

新增实验只需要明确的实验config、固定split、seed、模型/Prompt/检索/评分/指标配置、代码commit及必要输入输出hash。运行结果按dataset/model/backend/setting区分，旧正式与诊断结果不覆盖。不同设置使用清楚的结果目录即可，不默认创建新的protocol generation、authorization hierarchy、ledger或多层freeze身份。

实际语义变化才决定是否需要新实验版本；普通文档、日志、CLI修复、输出一致的优化无需自动创建successor protocol。判分改变gate、改变查询或scoring时，从最早受影响阶段生成明确的新结果，历史失败和事后结果继续保留。
