## 1. 本次（v8 → v9）改动总览

```text
1. L1 群体校准：用 Reserve 组当"非成员零分布",把 cg_cvg 升级为经验百分位 / z-score。
```

阶段定位仍是**可行性验证**（承接 v8 §2），不是冲顶会的完整实验。但本次把"成员信号是否

## 2. 改动一：L1 群体校准（Reserve 零分布）

### 2.1 为什么 `cg_cvg` 不够

`cg_cvg = cvg_rag − cvg_llm` 是一个**朴素的 per-example 校准**（用样本自己的 LLM-only 分减
先验），三个统计缺陷：

```text
① 零点估错：即便 x 非成员，RAG 也可能检索到语义近邻的成员文档，把 cvg_rag 抬高，
   所以非成员的 cg_cvg 期望并非 0；cvg_llm 捕捉不到这种"检索侧近邻泄漏"。
② 未校准方差：不同文档的 cg_cvg 在非成员世界下波动幅度不同，全局阈值对高方差样本不公平。
③ 只是点估计：A − B 没有统计语义，不是假设检验。
```

### 2.2 L1 做法

文件：`src/scoring/calibration.py`（新增）。用 `Reserve` 组当"非成员零分布"：

```text
- Reserve 同分布、非成员、与评估组（KB_Member / True_Non_Member）source 互斥；
  从第 05 步起纳入 benchmark，随主流水线 06→11 跑出 cvg_rag。
- 对每个待测样本，按其 cvg_rag 在 Reserve 分布中的位置算两种校准分（都写回每行）：
    pcv_score_calibrated   经验百分位（mid-rank 处理 ties），[0,1]，不假设正态、小样本稳；主分。
    pcv_score_calibrated_z z-score = (cvg_rag − μ_reserve) / σ_reserve。
- 评估指标必须排除 Reserve（它是校准料不是测试样本）。校准用 Reserve、评估用 True_Non，
  两者零重叠——这是不作弊的命门。
```

### 2.3 L1 的本质局限（重要）

```text
L1 经验百分位 / z-score 都是对 cvg_rag 的【全局单调变换】。AUC 只看排序，单调变换不改 AUC，
所以 L1 校准分的 AUC 恒等于 cvg_rag 的 AUC（实测 small 0.936=0.936、formal 0.835=0.835）。
=> L1 的价值不在"提升可分性(AUC)",而在：① 甩掉 cvg_llm 噪声 ② 给 [0,1] 跨样本标定
   ③ 低 FPR 区。想靠校准提升 AUC、扣 per-example 先验，必须上 L2（per-example、非单调）。
LLM-only 可视为"空 KB shadow"的极端特例，cg_cvg 是本框架在"参考只有一个、且空索引"时的
退化版本——旧设计被收编而非推翻；pcv_score(=cg_cvg) 字段保留不动。
```

## 3. 改动二：放大样本后的泄漏诊断（NO-GO 的真相）

把 small（KB/True_Non=100/100，scored=37）换成 formal（500/500，eval=256）后，方向性判定
从 GO 翻成 **NO-GO**，因为 `cvg_llm AUC=0.606 > 0.6`（v8 §4 判据 2）。诊断结论：

### 3.1 信号对照

```text
            small(n=37, 不可信)      formal(eval=256, 可信)
cvg_rag       0.936                   0.835   CI[0.788,0.879]
cvg_llm       0.438/0.508(噪声)        0.606   CI[0.542,0.672]  <- 下界>0.5,泄漏确凿
cg_cvg        0.895                   0.772   CI[0.716,0.828]
calibrated    0.936(=cvg_rag)         0.835(=cvg_rag)
TPR@1%FPR     cg_cvg .800/cal .867    cg_cvg .035 / cal .000
TPR@5%FPR     —                       cg_cvg .434 / cal .636
```

**small 的 0.936/GO 全部作废**：n=37 下 AUC 标准误 ~0.1，cvg_llm=0.438 是噪声，"GO"是假象。

### 3.2 根因（诊断脚本 `scripts/_diag_leakage.py`）

```text
排除项（KB 与 True_Non 高度均衡，故 NO-GO 不是切分 bug / 捷径 / 难度不平衡）：
  - entity_type 分布：两组几乎一致（MONEY/DATE/PERSON 占大头）。
  - fact 难度：attackability 0.695 vs 0.681，importance 0.766 vs 0.749，几乎一致。
  - 文本统计：长度 811 vs 796、entity_density 0.054 vs 0.048，几乎一致（shortcut AUC 也低）。

真正机制（LLM-only 无检索时两组行为差异）：
  Q+ support:   KB 0.30 vs True_Non 0.20      （KB 真值更易被无检索支持）
  Q- reject_cf: KB 0.55 vs True_Non 0.36      （KB 反事实更易被无检索识破）
  Q- correct:   KB 0.15 vs True_Non 0.05      （KB 先验里更"知道正确答案"）
=> KB 组的事实本身"先验可验证性"更高。最可能主因：enron 是著名公开数据集，victim(qwen3)
   预训练几乎肯定见过；叠加"可被检索验证的事实"与"可被先验验证的事实"天然正相关，随机
   切分两组的微小差异被大样本放大。应验了 v8 §5.5 的预言。

好消息（检索净增益真实强劲）：
  RAG Q+ support: KB 0.64 vs True_Non 0.03 ；RAG Q- correct: KB 0.54 vs True_Non 0.04。
  扣先验后的 cg_cvg AUC=0.772 CI[0.716,0.828] 仍显著>0.5——攻击没失效，只是先验必须诚实扣除。
```

### 3.3 两条结论

```text
- 污染数据上绝不能用 calibrated(=cvg_rag=0.835) 报数（它不扣先验，虚高）；要用扣先验的
  cg_cvg(0.772) 或 L2。
- feasibility 判据 2（cvg_llm≤0.6）对"模型见过的公开数据集"过于一刀切，会误报 NO-GO。
  对策：换更私密/模型没见过的数据集（让阴性对照回到≈0.5），或承认污染、主报扣先验终分。
```

## 4. 改动三：L2 shadow 逐样本校准（本次核心）

L1 是全局单调变换，扣不掉 §3 那种 **per-example 先验泄漏**。L2 对每个评估目标 x 估计它
**自己的**非成员零分布，从而逐样本扣先验。

### 4.1 算法（offline LiRA，Reserve-shadow）

```text
1. 从 Reserve 采 K 个子集，各建一个 shadow RAG 索引（纯 embedding、不花 API）。
   因 Reserve 与所有评估目标 source 互斥，K 个 shadow 对全体目标天然都是 OUT 世界
   —— 无需"每个 x 单独建不含 x 的库",K 个 shadow 全体目标共享（成本 = K 倍而非 N×K）。
2. 对评估 query 在每个 shadow 上跑 RAG（只跑 RAG 路：LLM-only 与索引无关、跨 shadow 不变，
   复用主 run 的，省 K 倍 LLM-only 调用）。
3. 同一目标 x 在 K 个 shadow 上的 cvg_rag 即其 OUT 分布 (μ_out(x), σ_out(x))。
4. victim 观测 = 主 run 的 cvg_rag(x)。per-example 标准化：
       z(x) = (cvg_rag_victim(x) − μ_out(x)) / σ_out(x)
       L2 分 = Φ(z)  ∈[0,1]，越高越像成员（offline LiRA 单边，等价 1 − p 值）
   μ_out(x) 逐样本包含 x 的先验可验证性，故 z 把 per-example 先验扣掉了。
   方差兜底（variance flooring）：σ_out(x) 为 0 或点数不足时，用全体 σ_out 中位数兜底。
```

### 4.2 为什么不能走"难度回归"省钱捷径

```text
§3.2 诊断显示先验泄漏不在任何可观测表层特征里（类型/难度/文本统计两组全均衡，泄漏却真实）。
=> 用可观测特征回归预测先验的 L2b 抓不到它。只有 shadow 能扣——它直接用 victim 模型在
   "无 x 检索"下的真实反应估先验，不依赖"先验可被特征解释"的假设。用自己的数据否决了捷径。
```

### 4.3 PCV-MIA 做 L2 的天然优势（论文卖点）

```text
传统 MIA 做 LiRA 要训练几百个 shadow model（成本爆炸）。PCV-MIA 的"模型"是 RAG 索引，
建 shadow 只是 re-embed + 重建索引（秒级、几乎免费），所以负担得起 per-example 校准。
```

### 4.4 go / no-go 闸门

```text
L2 分扣先验后应满足：True_Non 的 Φ(z)≈0.5（先验扣净）、KB→1，且 AUC > cg_cvg(0.772)。
做到则说明 L2 把 §3 的 0.606 泄漏扣干净了。
（离线单元测试已验证机制：一个 cvg_rag 与 KB 齐平的"高先验陷阱"非成员，被 L2 的
  per-example μ_out 识破为 z≈0，而 cvg_rag 被骗。真实数据上的 K-shadow 验证待跑。）
```
