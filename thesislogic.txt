我前面说“Conflict Resolution as Privacy Leakage”，不是让你放弃 MIA，而是让你把 **MIA 的攻击信号** 包装得更高级。

你现在真正的论文主线可以这样定义：

```text
Task: Membership Inference Attack against RAG Knowledge Bases
Signal: Conflict-Induced Entity Recovery
```

> **你的研究目标仍然是 MIA；
> 只是你的 MIA 不是传统 loss-based / similarity-based / mask-based，而是基于“事实冲突纠错行为”的新型 MIA。**

## 1. 怎么保持课题是 MIA？

你的核心问题仍然是这个：

```text
Given a candidate document x, determine whether x is a member of the RAG knowledge base.
```

形式化：

```text
H1: x ∈ D_KB    member
H0: x ∉ D_KB    non-member
```

这就是标准 MIA。

你的攻击输出也是：

```text
member / non-member
```

你的指标也是：

```text
AUC
TPR@1%FPR
TPR@5%FPR
FPR
Precision
Attack Success Rate
```

这些全都是 MIA 论文标准指标。

所以方向没有变。

---

## 2. “Conflict Resolution” 是 MIA 的攻击信号，不是新课题

你可以把它理解成：

| MIA 方法                   | 使用的信号                  |
| ------------------------ | ---------------------- |
| Loss-based MIA           | member loss 更低         |
| Perplexity MIA           | member perplexity 更低   |
| Similarity-based RAG-MIA | member response 更像原文   |
| Mask-based RAG-MIA       | member 更容易补回 mask      |
| Exam-style RAG-MIA       | member 问题更容易答对         |
| **你的方法**                 | **member 更容易触发错误实体恢复** |

所以你的创新不是离开 MIA，而是提出一种新的 membership signal：

```text
Conflict-Induced Entity Recovery Signal
```

```text
Can the correction behavior of RAG systems be exploited as a membership inference signal?
```

中文：

> RAG 系统在纠正用户错误事实时的行为，能否被利用为成员推理攻击信号？

这句话非常适合你的课题。

它里面同时包含：

```text
MIA 目标：membership inference
你的创新信号：correction behavior / conflict-induced recovery

```

## 5. 最终主线应该是这样

你的论文不是：

```text
我研究 RAG 事实冲突。
```

而是：

```text
我研究 RAG 知识库成员推理攻击。
现有方法依赖语义相似度、mask 补全或问答正确率。
我提出一种新的 MIA 信号：当候选文档在知识库中时，RAG 更可能用私有检索证据纠正用户输入中的错误实体。
```

这就完全是 MIA。

---

## 6. 你可以这样定义方法

### 方法名称

```text
CIR-MIA
Conflict-Induced Recovery Membership Inference Attack
```

### 输入

```text
候选文档 x
目标 RAG 系统 R
```

### 操作

```text
1. 从 x 中抽取关键实体 e
2. 将 e 替换为合理但错误的实体 e'
3. 构造自然校对/核验查询 q(x, e')
4. 发送给 RAG 系统
5. 观察系统是否恢复 e
```

### 输出

```text
如果恢复原实体 e 的概率高，则判定 x 是 member
否则判定 x 是 non-member
```

这就是一个完整的 MIA 攻击。

---

## 7. 你现在的创新点应该这样归纳

不要写成：

```text
我们研究 RAG 纠错。
```

要写成：

```text
我们提出了一种新的 RAG-MIA 攻击范式：Conflict-Induced Recovery MIA。
```

贡献可以写成：

```text
1. We formulate conflict-induced entity recovery as a new membership inference signal for RAG systems.

2. We propose CIR-MIA, a black-box MIA that replaces factual entities in a candidate document with plausible incorrect alternatives and infers membership from whether the RAG system restores the original entities.

3. We introduce CMS, a multi-entity, multi-query membership score, and a difficulty-calibrated variant to reduce false positives.

4. We construct counterfactual hard non-members to control for style, entity density, and semantic similarity.

5. We evaluate CIR-MIA against existing RAG-MIA baselines, including semantic similarity, mask-based, exam-style, and direct-query attacks.
```

这样每一点都围绕 MIA。

---

## 8. 为什么“冲突解析”仍然服务于 MIA？

因为你不是单纯研究：

```text
模型怎么处理冲突
```

而是利用冲突处理行为来判断：

```text
目标文档是否在知识库中
```

也就是：

```text
Conflict Resolution → Membership Signal → MIA Decision
```

完整链条：

```text
候选文档在知识库中
→ 毒化 query 仍然检索到它
→ 检索上下文包含原始实体
→ RAG 发现用户实体和知识库实体冲突
→ RAG 恢复原实体
→ 攻击者推断该文档是 member
```

这条链的最终目标就是 MIA。

---

## 9. 你可以把论文定位成这句话

最准确的定位是：

> **本文研究一种针对 RAG 知识库的新型成员推理攻击。我们发现，当攻击者将候选文档中的关键实体替换为合理错误实体后，RAG 系统若能利用私有知识库纠正该错误，则这种“冲突诱导恢复”行为会泄露候选文档的成员状态。**

这句话完全没偏离 MIA。

你的课题还是 MIA，只是应该从：

```text

```

升级为：

```text
行为型 MIA：看系统是否在事实冲突中恢复私有实体
```

最终建议你用这个主线：

```text
CIR-MIA: A Conflict-Induced Entity Recovery Membership Inference Attack against RAG Systems
```

一句话：

> **MIA 是你的任务，Conflict-Induced Recovery 是你的攻击信号，RAG 是你的应用场景。**
