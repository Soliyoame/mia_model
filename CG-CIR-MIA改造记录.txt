创建时间：2026-05-07

全称：Context-Gain Calibrated Conflict-Induced Recovery Membership Inference Attack


一、本次改造目标
----------------

本次任务不是从零新建一个无关项目，而是在当前已有 MIA 项目代码基础上进行重构和扩展。

原项目核心方向：
微调 LLM 成员推理攻击。

改造后的核心方向：
面向 RAG 知识库的 CG-CIR-MIA 成员推理攻击框架。

核心思想：
1. 对候选文档抽取关键实体。
2. 把关键实体替换成“合理但错误”的同类型实体。
3. 构造自然的验证、审计、校对类 query。
4. 同一条 query 分别运行 RAG 模式和 LLM-only 模式。
5. 如果 RAG 能恢复原始实体，而 LLM-only 不能恢复，则恢复更可能来自 RAG 知识库。
6. 用 CG-CMS = CMS_RAG - CMS_LLM 作为 membership score。
7. 攻击目标是判断候选文档是否存在于 RAG 知识库中。


二、重要实验边界
----------------

本次改造必须严格满足以下约束：

1. 不实现 Twin_Non_Member。
2. 保留 Spoofed_Non_Member。
3. 主实验分组只有：
   - KB_Member
   - True_Non_Member
   - Spoofed_Non_Member
4. 只有 KB_Member 可以进入 RAG 知识库。
5. True_Non_Member、Spoof_Seed、Spoofed_Non_Member、Reserve 绝对不能进入 RAG 知识库。
6. retrieved_doc_ids、retrieval_scores、target_doc_retrieved 只能用于机制分析，不能用于 black-box 攻击判定。
7. 所有中间结果统一保存为 JSONL。
8. 所有阶段要有 logging、tqdm 进度条、manifest 文件和 --force 断点续跑能力。
9. LLM API、Sibling LLM、Victim/RAG Generator 均接口化，不硬编码 API key。
10. 优先复用当前已有代码，不做无意义删除。

五、计划执行步骤
----------------

阶段 1：梳理现有代码
- 阅读 README.md、configs、src/data、src/prepare、src/attack、src/llm、tests。
- 记录哪些代码可以复用，哪些需要移动或改造。

阶段 2：补齐基础设施
- 统一 JSONL IO。
- 统一 manifest 写入。
- 统一配置加载。
- 统一 logging。
- 增加 --force 跳过/重跑逻辑。
- 保证 Windows 路径兼容。

阶段 3：数据标准化和切分
- 改造 preprocess。
- 支持 Enron、CUAD、EDGAR、PubMed 本地数据。
- 实现四组互斥切分。
- 生成 split_manifest。

阶段 4：RAG 知识库
- 新增 RAG index builder。
- 接入 embedding client。
- 支持 FAISS。
- 保存 faiss.index、docstore.jsonl、index_manifest.json。
- 强制校验只有 KB_Member 进入 index。

阶段 5：Spoofed_Non_Member
- 用 Sibling LLM client 接口生成改写候选。
- mock 模式可先跑通流程。
- 实现质量评分和阈值过滤。
- 输出 spoof_manifest 和统计。

阶段 6：Attack Benchmark
- 合并 KB_Member、True_Non_Member、Spoofed_Non_Member。
- 写入 benchmark jsonl 和 manifest。
- 明确 in_knowledge_base 标签。

阶段 7：实体抽取、扰动和 query 生成
- 规则抽取 MONEY、DATE、PERCENT、NUMERIC_VALUE、MEDICAL_VALUE、CONTRACT_TERM。
- NER 抽取 PERSON、ORG、LOCATION。
- Sibling LLM 辅助 importance、replaceability、privacy_specificity。
- 生成 conflict sample。
- 构造自然冲突 query。
- stealth filter 过滤可疑 query。

阶段 8：RAG 与 LLM-only 双模式运行
- RAG：query -> retriever -> context -> generator -> response。
- LLM-only：query -> generator -> response。
- 同一 generator，不提供 retrieved context。
- 输出 rag_responses 和 llm_only_responses。

阶段 9：解析和打分
- 解析是否恢复 original_entity、是否保留 conflict_entity、是否拒答、是否 unknown。
- 计算 recovery level。
- 聚合 CMS_RAG、CMS_LLM、CG-CMS。
- 实现默认 threshold 和低误报规则。

阶段 10：baseline、机制分析、防御、报告
- 实现 baseline 接口和可运行 stub。
- 实现机制分析统计。
- 实现防御实验接口。
- 生成 final_report.json 和 summary.md。

阶段 11：README 和测试
- 更新 README.md，写清楚小白可运行步骤。
- 增加基础测试。
- 至少保证小规模 Enron mock 流程可跑通。
