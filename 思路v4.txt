下面给你一份**重新整理后的最终代码思路方案**：
**保留 Spoofed_Non_Member，删除 Twin_Non_Member**，主线改成针对 **RAG 知识库成员推理攻击** 的版本。

方法名建议：

```text
CG-CIR-MIA
Context-Gain Calibrated Conflict-Induced Recovery Membership Inference Attack
```

核心定位：

> 给 RAG 系统输入一个“合理但错误的实体事实”，观察它是否用私有知识库中的原始实体纠正该错误；再用 RAG 输出和 LLM-only 输出的差值判断该纠正是否真的来自知识库。

# 1. 总体目标

你的系统最终要解决的问题是：

```text
给定一篇候选文档 x，
判断 x 是否存在于 RAG 的私有知识库中。
```

也就是标准 MIA：

```text
member: x ∈ D_KB
non-member: x ∉ D_KB
```

攻击信号不是 loss、相似度、mask 补全，而是：

```text
Conflict-Induced Entity Recovery
```

即：

```text
用户输入错误实体
↓
RAG 检索私有知识库
↓
如果目标文档在库中，RAG 可能恢复原实体
↓
恢复行为成为 membership signal
```

上传的 IA 论文已经证明“自然 query + 多问题聚合 + 黑盒 RAG-MIA”是强 baseline，所以你的方案不能只做自然问答，而要突出“反事实实体冲突 + RAG/LLM-only 上下文增益校准”。该论文还强调 query rewriting、stealth detection、UNK penalty、query 数量消融、top-k 消融等实验设计，这些都应该吸收到你的框架里。


```text
semantic_preservation
entity_preservation
style_match
length_match
entity_density_match
```

保留满足以下条件的候选：

```text
naturalness >= 8
fluency >= 8
semantic_preservation >= 8
entity_preservation >= 8
style_match >= 8
```

为了让 Spoof 更有说服力，需要统计它和 KB_Member 的分布差异：

# 12. Stage 8：Stealth Filter

## 目标

筛掉太像攻击的 query。

上传 IA 论文的一个重要结论是：很多已有 RAG-MIA / extraction attack 的 query 很容易被检测器识别，而自然 query 的检测率很低。你这里必须加入 stealth 检测，否则“自然攻击”的说服力不够。

## 检测维度

```text
是否像 prompt injection
是否像 context probing
是否要求泄露 context
是否询问 membership
是否包含 repeat context / hidden document / database / indexed 等危险词
query-document similarity
query 长度
自然度评分
```

## 输出字段

```text
query_id
naturalness_score
context_probe_score
prompt_injection_score
query_doc_similarity
accepted
reject_reason
```

未通过的 query 需要重新生成。

# 13. Stage 9：同时运行 RAG 和 LLM-only

这是你方案区别于普通 RAG-MIA 的核心。

## 13.1 RAG 模式

```text
query
↓
query rewriting 可选
↓
retriever
↓
top-k context
↓
generator
↓
response
```

## 13.2 LLM-only 模式

```text
同一个 query
↓
不提供 retrieved context
↓
直接调用同一个 generator
↓
response
```

## 为什么要做 LLM-only？

因为有些实体纠正可能来自模型自身知识，而不是 RAG 知识库。

所以你需要计算：

```text
RAG 比 LLM-only 多出来的实体恢复能力
```

这就是：

```text
Context Gain
```

如果：

```text
RAG 恢复原实体
LLM-only 不恢复
```

这是强 membership signal。

如果：

```text
RAG 恢复
LLM-only 也恢复
```

说明可能是模型自身知识，不能作为强证据。

# 15. Stage 11：单次响应打分

## 打分等级

```text
Level 3：强恢复
出现 original_entity，并明确否定或替换 conflict_entity
score = 1.0

Level 2：中恢复
指出 conflict_entity 不一致，但未给出 exact original_entity
score = 0.6

Level 1：弱恢复
删除、模糊化、规避 conflict_entity
score = 0.3

Level 0：无恢复
保留 conflict_entity，或回答 consistent
score = 0

Level -1：UNK / I don't know
score = -λ
```

其中 `λ` 是 UNK penalty。

IA 论文中使用了对 “I don’t know” 的惩罚项，因为 non-member 更容易无法回答；你这里可以吸收这个思想。

# 20. Stage 16：防御实验

## Defense 1：Conflict-aware Non-disclosure

当用户输入实体与 retrieved context 冲突时，不输出正确实体，只说存在冲突。

```text
The available documents contain a conflicting value, but I cannot disclose the exact value.
```

## Defense 2：Entity Redaction

检索上下文进入 generator 前，对敏感实体做遮蔽：

```text
[REDACTED_AMOUNT]
[REDACTED_DATE]

```
