🌟 一、 架构总览：从“动态流水线”到“两阶段物理隔离”
为了实现对微调模型（Fine-tuned Model）的攻击，整个系统的生命周期必须被拦腰截断，分为两个绝对物理隔离的阶段。

核心痛点解决：以前你的代码是一次性跑完“造假、下毒、攻击”，这就导致你无法把 True_Member 提前拿出来去微调模型。

新架构核心：引入**“静态基准文件（Static Benchmark）”**概念。第一阶段只负责造数据并“冻结（Freeze）”到本地硬盘；用户拿着数据去微调；第二阶段只负责读取冻结的数据发起黑盒探针攻击。

📦 二、 核心数据流产物（The Artifacts）
系统重构后，第一阶段必须产出两个极其关键的 JSON 文件，它们是连接两个阶段的桥梁：

sft_training_data.json (微调弹药库)：

作用：直接喂给 LLaMA-Factory 等微调框架的训练数据。

内容：只有 True_Member 的原始文本。它会被包装成标准的 Instruction 格式（例如：“请记住以下内部保密文档：[文本]”）。

audit_benchmark.json (静态打靶基准)：

作用：固定下来的测试集，保证攻击阶段的数据绝对不发生漂移。

内容：包含三类数据（True_Member, True_Non_Member, Spoofed_Non_Member）的完整列表，每条记录包含其原始文本、真实标签、以及生成时的流畅度打分等元数据。

🛠️ 三、 阶段一：靶场制备层 (prepare 模式逻辑)
执行者：Sibling LLM（小杯模型，如 DeepSeek）
核心目标：划分数据，生成伪造对照组，固化并导出两个核心 JSON。

详细步骤逻辑：

数据采样与切割：

从指定数据集（如 enron_emails）中随机抽取预设数量（如 100 条）作为 True_Member。

再抽取同等数量作为 True_Non_Member 和后续用于伪造的种子数据。

生成伪造非成员（高流畅度洗白）：

调用 SpoofedNonMemberGenerator，让 Sibling LLM 对种子非成员数据进行重写。

调用 LLM-as-a-Judge 进行严格打分，仅保留 ≥9 分的完美伪造文本，标记为 Spoofed_Non_Member。

固化打包与双向导出：

动作 A：将所有 True_Member 提取出来，组装成 LLaMA-Factory 支持的 SFT 格式，写入本地 sft_training_data.json。

动作 B：将三组数据（真实成员、真实非成员、伪造非成员）汇总成一个列表，打上明确的 source_type 标签，完整写入本地 audit_benchmark.json。

阶段一结束：程序安全退出，等待用户进行模型微调。

⚔️ 四、 阶段二：实弹攻击层 (attack 模式逻辑)
执行者：Sibling LLM（负责下毒） + Victim LLM（微调后的目标模型，负责接招）
核心目标：读取基准数据，实施知识冲突探针，出具最终安全审计报告。

详细步骤逻辑：

静态基准加载：

跳过所有随机抽样逻辑，直接从硬盘读取 audit_benchmark.json。

逻辑锁：校验该文件是否包含三类完整数据，确保对照组完备。

运行时知识下毒（Perturbation）：

遍历读取到的每一条基准文本。

调用 KnowledgePerturbator，利用 Sibling LLM 找出原文中的“硬事实实体（年份、人名）”，将其无痕篡改为错误实体。

注意：篡改必须在运行时进行，因为我们要保证“带毒文本”绝对没被微调模型见过。

黑盒探针审讯（Probing）：

将带毒文本放入“校对指令（Proofreading Prompt）”中。

将指令发送给 Victim LLM API（此时是用户挂载在 localhost:8000 的微调模型），强制 Temperature = 0。

获取模型的校对返回结果。

三路分支仲裁与指标统计（Adjudication）：

调用 BlackboxAuditor 的判决器，对比输出结果与原实体/篡改实体。

如果微调模型把篡改的词改回了微调数据集里的原词，判定为 Member（触发强迫纠错）。

统计并打印出你在上一次实验中看到的那种极其严谨的 TPR / FPR 表格。

🏗️ 五、 代码模块的重构映射表 (Refactoring Map)
为了实现上述思路，你的代码目录结构不需要大动，只需要做以下手术：

src/pipeline.py (改动最大)：

废弃原来的 audit() 方法。

新增 prepare_benchmark(dataset_name, output_sft_path, output_benchmark_path) 方法，封装阶段一。

新增 run_attack(benchmark_path, output_results_path) 方法，封装阶段二。

main.py (命令行入口层)：

使用 argparse 的 subparsers 功能，将原来的单命令行拆分为两个子命令：

python main.py prepare --dataset ... --export-sft ...

python main.py attack --benchmark ... --victim-url ...

src/audit_data.py, perturbator.py, blackbox_auditor.py (几乎零改动)：

这些底层工具类完全不受影响，它们的职责非常内聚。只需在 pipeline.py 中换一种方式调用它们即可。

总结：这套逻辑蓝图将你的系统从一个“单次运行的测试脚本”，正式升级为了一个**“涵盖数据生成、投毒、黑盒探测的工业级大模型安全靶场”**。逻辑极其清晰，变量绝对受控，是安全顶会最喜欢的实验范式！
